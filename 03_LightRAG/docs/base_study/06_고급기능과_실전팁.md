# 06. 고급 기능과 실전 팁

## Reranker

Reranker는 검색된 chunk를 더 정교한 관련도 모델로 다시 정렬한다. LightRAG는 reranker가 있을 때 query 품질이 좋아질 수 있으며, 공식 문서는 reranker 사용 시 `mix` mode를 권장한다.

지원 provider:

- Cohere / vLLM compatible rerank API
- Jina AI
- Aliyun

예시:

```env
RERANK_BINDING=cohere
RERANK_MODEL=BAAI/bge-reranker-v2-m3
RERANK_BINDING_HOST=http://localhost:8000/rerank
RERANK_BINDING_API_KEY=your_key
```

기본 rerank 사용 여부:

```env
RERANK_BY_DEFAULT=True
```

API 요청에서 query별로 끌 수도 있다.

```json
{
  "query": "What is the relation between A and B?",
  "mode": "mix",
  "enable_rerank": false
}
```

## Multimodal: RAG-Anything 통합

LightRAG는 `RAG-Anything`과 통합해 PDF, Office 문서, 이미지, 표, 수식 등 멀티모달 문서를 처리할 수 있다.

설치:

```bash
pip install raganything
```

주요 기능:

- PDF, DOC/DOCX, PPT/PPTX, XLS/XLSX, 이미지 처리
- 이미지, 표, 수식 전용 processor
- 멀티모달 지식 그래프
- 텍스트와 멀티모달 content를 함께 검색

실전에서는 기존 LightRAG instance를 만들고, 이를 `RAGAnything`에 연결하는 방식으로 쓴다.

## Token Usage Tracking

LLM 비용을 추적하려면 `TokenTracker`를 쓴다.

```python
from lightrag.utils import TokenTracker

token_tracker = TokenTracker()

rag = LightRAG(
    working_dir="./rag_storage",
    llm_model_func=llm_model_func,
    llm_model_kwargs={"token_tracker": token_tracker},
    embedding_func=embedding_func,
)

await rag.initialize_storages()

token_tracker.reset()
await rag.ainsert(["document one", "document two"])
answer = await rag.aquery("your question", param=QueryParam(mode="mix"))
print(token_tracker.get_usage())
```

LLM cache hit는 provider 호출을 만들지 않으므로 token usage가 증가하지 않을 수 있다.

## Knowledge Graph Export

지식 그래프를 분석하거나 백업하려면 export를 사용한다.

```python
rag.export_data("knowledge_graph.csv")
rag.export_data("knowledge_graph.xlsx", file_format="excel")
rag.export_data("knowledge_graph.md", file_format="md")
rag.export_data("knowledge_graph.txt", file_format="txt")
```

vector까지 포함:

```python
rag.export_data("complete_data.csv", include_vector_data=True)
```

## Cache 관리

전체 LLM cache 삭제:

```python
await rag.aclear_cache()
```

또는:

```python
rag.clear_cache()
```

query 관련 cache만 선택적으로 정리하려면 공식 tool인 `lightrag.tools.clean_llm_query_cache`를 확인한다.

## Langfuse 관측성

OpenAI-compatible LLM call을 추적하려면 observability extra를 설치한다.

```bash
pip install lightrag-hku[observability]
```

`.env`:

```env
LANGFUSE_SECRET_KEY=
LANGFUSE_PUBLIC_KEY=
LANGFUSE_HOST=https://cloud.langfuse.com
LANGFUSE_ENABLE_TRACE=true
```

주의: 공식 문서 기준 Langfuse integration은 OpenAI-compatible API 호출 중심이다. Ollama, Azure, AWS Bedrock 등은 아직 동일하게 지원되지 않을 수 있다.

## RAGAS 평가

LightRAG는 RAGAS 기반 평가 스크립트를 제공한다. 검색 context까지 반환하는 API 옵션과 함께 쓰면 context precision 같은 지표를 확인하기 쉽다.

평가/디버깅용 query 예:

```json
{
  "query": "What is LightRAG?",
  "mode": "mix",
  "include_references": true,
  "include_chunk_content": true
}
```

## 품질을 높이는 실전 팁

1. query와 출력 지시를 분리한다.

나쁜 예:

```text
표로 정리해서 Scrooge의 관계를 설명해줘.
```

좋은 예:

```python
await rag.aquery(
    "Scrooge의 주요 인물 관계는 무엇인가?",
    param=QueryParam(
        mode="mix",
        user_prompt="표로 정리하고, 마지막에 핵심 요약을 추가해줘.",
    ),
)
```

2. 처음에는 작은 corpus로 인덱싱 품질을 확인한다.

엔티티가 너무 잘게 쪼개지거나 중복되면 entity type, language, prompt 설정, 모델 품질을 조정한다.

3. embedding은 처음부터 신중히 고른다.

embedding dimension이 storage schema에 반영될 수 있다. 바꾸면 재인덱싱 비용이 생긴다.

4. 운영에서는 reranker를 테스트한다.

특히 `mix` mode + reranker 조합은 검색 precision 개선에 도움이 될 수 있다.

5. 대형 문서는 나눠서 넣는다.

큰 파일 하나가 실패하면 재처리 비용이 커진다. 작은 단위로 나누면 incremental processing이 쉬워진다.

6. 출처 경로를 넣는다.

`file_paths`를 넣으면 citation과 traceability가 좋아진다.

7. storage와 workspace를 운영 전에 설계한다.

나중에 storage를 바꾸는 것은 간단하지 않다. 팀/고객/프로젝트별 workspace 정책도 먼저 정한다.

## 트러블슈팅 요약

| 증상 | 확인할 것 |
|---|---|
| 초기화 오류 | `await rag.initialize_storages()` 호출 여부 |
| query 결과가 이상함 | mode, reranker, top_k, chunk_top_k, user_prompt 분리 |
| embedding 오류 | embedding model/dim 변경 여부 |
| 인덱싱이 느림 | LLM 성능, `MAX_ASYNC`, `MAX_PARALLEL_INSERT`, cache |
| 문서 업로드 실패 | proxy upload size, `MAX_UPLOAD_SIZE`, timeout |
| Open WebUI 연동 문제 | Ollama-compatible endpoint, model name `lightrag:latest`, prefix |
| 외부 노출 보안 문제 | API key와 JWT auth 동시 설정, whitelist 점검 |
