## 분석

### VDB vs LLM 순위 역전

"기넥신 부작용" 쿼리에서 벡터 유사도와 LLM 평가 순위가 크게 다르다.

- **VDB 1위** (약리 작용, vdb=0.5482) → **LLM 4위** (0.817): 부작용 직접 언급 없음
- **VDB 3위** (이상 반응, vdb=0.5352) → **LLM 1위** (1.000): 위장장애·신경계·피부 반응 직접 언급
- **VDB 7위** (리넥신 p.31, vdb=0.5170) → **LLM 8위** (0.600): 제품명 불일치 — constraint 0/3

VDB 10개 문서의 유사도 점수가 0.5065 ~ 0.5482로 편차가 **0.042** 밖에 없어, 벡터 유사도만으로는 순위 구분이 어렵다. LLMReranker가 실질적인 관련성 판단을 담당하고 있음을 확인.

### 프롬프트 수정 효과

프롬프트에 제품명 일치 조건을 명시한 결과:

| 항목                         | 1차 (수정 전)    | 2차 (수정 후)  |
| ---------------------------- | ---------------- | -------------- |
| 리넥신 doc (p.31) rank       | **3위**          | **8위**        |
| 리넥신 doc (p.31) score      | 0.967            | 0.600          |
| 리넥신 doc (p.31) constraint | **3/3** (과평가) | **0/3** (정확) |
| 리넥신 doc (p.25) rank       | 8위              | 10위           |
| 리넥신 doc (p.25) constraint | 3/3              | **0/3** (정확) |

**결론**: Relevance·Constraint Fit 기준에 제품명 불일치 시 점수 제한 규칙을 추가하여:

1. 리넥신 문서가 기넥신 쿼리에서 상위권을 차지하는 문제 해소 (rank 3 → rank 8/10)
2. LLM 판단이 명확해져 응답 속도 8.32s → 1.37s로 **6초 단축**
3. 저장 방법 문서 (기넥신, threshold 미달): 2차에서는 score=0.600으로 통과 — 프롬프트 수정이 관련 기준 전반에 영향을 미침

## 분석

### VDB vs LLM 순위 역전

쿼리 "내과 밑 약국 추천 약품"에서도 벡터 유사도 순위와 LLM 평가 순위가 크게 다르다.

- **VDB 2위** (병용 불가 제품 단문, vdb=0.5320) → **LLM 10위** (0.320): 내용 빈약
- **VDB 10위** (오메드 MR 시나리오, vdb=0.4861) → **LLM 2위** (0.755): 실무 적용성 높음
- **VDB 7위** (PM_Answer_Q56, vdb=0.4884) → **LLM 5위** (0.700): "내과 틈새품목" 쿼리 직접 매칭

### 0~10 척도 세분화 효과

기존 0~3 척도에서는 유사한 문서들이 모두 `2/3`으로 동일하게 평가되어 순위 구분이 어려웠다. 0~10 척도로 변경 후:

- rank 1~6 사이 점수 범위: 0.700 ~ 0.780 (이전 척도로 표현 불가능한 세분화)
- rank 7~10은 0.320 ~ 0.585로 명확히 분리
- `specificity` 점수가 8/10 vs 7/10으로 갈리면서 실질적 순위 차별화 가능

### 특이사항

- **rank 8** (통풍 약제 문서): 소화기 중심 쿼리에 통풍 약제(세레브릭스·아크로신)가 포함 — constraint 0/10으로 하위권 배치됨
- **rank 10** (VDB 2위→LLM 10위): 단 1문장짜리 문서("병용불가 제품 없음")가 임베딩 유사도는 높았으나 정보 밀도 부족으로 대폭 하락
- **threshold 0.3 기준**: 최저 점수 0.320으로 모두 통과 — 쿼리가 광범위할수록 관련 문서가 많아 필터링이 덜 일어나는 패턴 확인
