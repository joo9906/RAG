# 02. 설치와 빠른 시작

## 설치 방식 선택

LightRAG는 크게 세 가지 방식으로 시작할 수 있다.

| 방식 | 추천 상황 |
|---|---|
| PyPI 설치 | 빠르게 서버나 Core를 써보고 싶을 때 |
| Source 설치 | 개발, 커스터마이징, 최신 코드 확인 |
| Docker Compose | 서버/WebUI/스토리지를 함께 운영 |

공식 문서는 `uv` 사용을 권장하지만, `pip`도 사용할 수 있다.

## LightRAG Server 설치

서버와 WebUI/API를 쓰려면 `api` extra를 포함해 설치한다.

```bash
uv tool install "lightrag-hku[api]"
```

pip를 쓴다면:

```bash
python -m venv .venv
.venv\Scripts\activate
pip install "lightrag-hku[api]"
```

## LightRAG Core 설치

Python 코드에서 직접 `LightRAG` 클래스를 쓰려면 Core만 설치해도 된다.

```bash
uv pip install lightrag-hku
```

또는:

```bash
pip install lightrag-hku
```

## 소스에서 설치

```bash
git clone https://github.com/HKUDS/LightRAG.git
cd LightRAG
make dev
```

수동으로는 다음 흐름이다.

```bash
uv sync --extra test --extra offline
.venv\Scripts\activate
cd lightrag_webui
bun install --frozen-lockfile
bun run build
cd ..
```

## Docker Compose 실행

```bash
git clone https://github.com/HKUDS/LightRAG.git
cd LightRAG
copy env.example .env
docker compose up
```

실행 전 `.env`에서 LLM과 embedding 설정을 반드시 맞춰야 한다.

## 첫 실행 전 필수 설정

LightRAG에는 최소한 다음이 필요하다.

- LLM provider와 model
- embedding provider와 model
- embedding dimension
- 필요하면 reranker
- storage backend 선택

OpenAI LLM + Ollama embedding 예시는 다음과 같다.

```env
LLM_BINDING=openai
LLM_MODEL=gpt-4o
LLM_BINDING_HOST=https://api.openai.com/v1
LLM_BINDING_API_KEY=your_api_key

EMBEDDING_BINDING=ollama
EMBEDDING_BINDING_HOST=http://localhost:11434
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_DIM=1024
```

Ollama LLM + Ollama embedding 예시는 다음과 같다.

```env
LLM_BINDING=ollama
LLM_MODEL=mistral-nemo:latest
LLM_BINDING_HOST=http://localhost:11434
OLLAMA_LLM_NUM_CTX=16384

EMBEDDING_BINDING=ollama
EMBEDDING_BINDING_HOST=http://localhost:11434
EMBEDDING_MODEL=bge-m3:latest
EMBEDDING_DIM=1024
```

## Setup Wizard

소스 설치 기준으로 `.env`를 직접 수정하기 어렵다면 wizard를 쓴다.

```bash
make env-base
make env-storage
make env-server
make env-security-check
```

각 명령의 역할:

| 명령 | 역할 |
|---|---|
| `make env-base` | LLM, embedding, reranker 설정 |
| `make env-storage` | PostgreSQL, Neo4j, Redis, Milvus, Qdrant 등 저장소 설정 |
| `make env-server` | 포트, 인증, API key, SSL 설정 |
| `make env-security-check` | 배포 전 보안 설정 점검 |

## 서버 시작

```bash
lightrag-server
```

기본 포트는 `9621`이다.

- Swagger UI: `http://localhost:9621/docs`
- ReDoc: `http://localhost:9621/redoc`

## 모델 선택 기준

공식 문서 기준 권장사항:

- LLM은 32B 이상급 모델 권장
- context length는 최소 32KB, 가능하면 64KB 권장
- 인덱싱 단계에서는 reasoning model을 피하는 것이 좋음
- 질의 단계에서는 인덱싱보다 강한 모델을 쓰면 답변 품질이 좋아질 수 있음
- embedding은 `BAAI/bge-m3`, `text-embedding-3-large` 같은 검증된 모델 권장
- reranker는 `BAAI/bge-reranker-v2-m3`, Jina 계열 등을 고려

## 중요한 주의사항

embedding 모델, 차원, asymmetric embedding 설정을 바꾸면 기존 벡터 데이터와 맞지 않을 수 있다. 이 경우 기존 workspace/vector data를 지우고 문서를 다시 인덱싱해야 한다.
